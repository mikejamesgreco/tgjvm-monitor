TGJVM Monitor Help

TGJVM Monitor uses the local PowerShell bridge and standard JDK tools to observe a JVM without changing the target application. The normal live loop uses lightweight jstat snapshots. Heavier diagnostics, such as a class histogram, are deliberately manual.

Poll Interval

Meaning: How often the browser asks the bridge for a new live snapshot.

Developer: Shorter intervals make short GC/memory changes easier to see.

Administrator: Longer intervals reduce monitoring overhead. The default 2 seconds is a practical general-purpose rate.

Heap Used

Meaning: Approximate used Java heap from the currently active survivor spaces, Eden, and Old Gen.

Developer: A steadily rising floor after collections can suggest retained objects or a leak.

Administrator: Shows memory pressure and how close the JVM is operating to its currently committed heap capacity.

Heap Capacity

Meaning: Capacity currently represented by the sampled young and old heap regions, not necessarily the JVM's configured maximum heap.

Developer: Helps distinguish real object growth from normal JVM heap resizing.

Administrator: Useful when comparing working heap size with host memory availability.

Eden Used

Meaning: Memory occupied in Eden, where most new objects are first allocated.

Developer: Rapid growth and reset is normal; very high allocation churn can point to excessive temporary-object creation.

Administrator: High churn often corresponds with frequent young collections and additional CPU work.

Old Gen Used

Meaning: Memory occupied by objects that have survived long enough to be promoted into the old generation.

Developer: One of the most useful leak indicators. Watch whether the post-GC baseline keeps increasing.

Administrator: Sustained old-generation pressure increases the chance of expensive full collections or memory exhaustion.

Metaspace Used

Meaning: Native memory used mainly for loaded class metadata.

Developer: Unexpected growth can indicate excessive dynamic class generation or class-loader retention.

Administrator: Metaspace is outside the normal Java heap and still consumes process/host memory.

Survivor 0 / Survivor 1

Meaning: The two survivor spaces used by the young generation to hold objects that survive a young collection.

Developer: Helps show how many objects survive long enough to move beyond Eden and potentially become promoted to Old Gen.

Administrator: Persistent survivor pressure can contribute to promotion pressure and eventually higher Old Gen usage.

Compressed Class Space

Meaning: Memory used for compressed class pointers and related class metadata when the JVM uses compressed class pointers.

Developer: Unexpected growth can accompany heavy class loading or class-loader retention.

Administrator: It is native JVM memory outside the ordinary object heap and therefore contributes to process memory consumption.

Young GC / Young GC Time

Meaning: Count and accumulated elapsed time for young-generation collections.

Developer: Shows how often short-lived allocations are being cleaned up and the cumulative cost.

Administrator: A rapidly increasing count/time can indicate allocation pressure and CPU overhead.

Full GC / Full GC Time

Meaning: Count and accumulated elapsed time for full/major collections reported by the JVM.

Developer: Frequent full collections deserve investigation, especially alongside rising Old Gen.

Administrator: Full collections can create significant pauses and are important for latency and service health.

Total GC Time

Meaning: Young GC time plus Full GC time from the sampled counters.

Developer: A simple indication of how much elapsed JVM lifetime has been spent collecting.

Administrator: Useful for spotting increasing GC cost while watching application responsiveness.

Top Live Classes / Objects

Meaning: A point-in-time class histogram showing live instance counts and bytes by class.

Developer: Helps identify which object types dominate memory and can focus leak investigations.

Administrator: Useful evidence when a JVM is consuming unexpected memory before escalation to deeper profiling.

Memory History Graph

Meaning: A rolling time series of used heap, sampled heap capacity, and Old Gen usage.

Developer: The shape is often more useful than a single number: healthy allocation commonly looks saw-toothed, while a rising post-GC baseline deserves attention.

Administrator: Makes sustained pressure, abrupt growth, and capacity changes visually obvious.

Leading Edge

Meaning: Controls which side of the graph receives the newest sample.

Developer: Choose Right for the conventional time-series view or Left for a scope-style view where new samples enter from the left.

Administrator: The y-axis labels follow the selected leading edge so current values remain visually adjacent to the newest data.

Local JVM Bridge

Required companion: TGJVM Monitor communicates with the local PowerShell bridge script tg-jvm-bridge.ps1, which listens on http://localhost:32032 and invokes standard JDK diagnostic tools on behalf of the browser.

Start it: From the directory containing the script, run powershell -ExecutionPolicy Bypass -File .\tg-jvm-bridge.ps1, then open TGJVM Monitor and use Discover JVMs.

Why it exists: A browser cannot directly execute jstat or jcmd. The bridge provides a small, local-only HTTP interface using predefined monitoring commands rather than accepting arbitrary operating-system commands.

Project documentation: Use GitHub / Docs ↗ beneath the TGJVM branding or GitHub / README ↗ in the footer to open the public repository, README, source, and release resources.

Monitoring Scope

Meaning: TGJVM is a lightweight observation tool, not a replacement for JFR, a full profiler, or production APM.

Developer: Use it to get oriented quickly, then move to deeper tooling when the evidence warrants it.

Administrator: It is designed to minimize setup and monitoring impact while exposing common JVM health signals.
